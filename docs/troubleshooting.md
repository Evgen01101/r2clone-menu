# Ошибки и их причины

Разбор типовых сбоев R2clone menu. Быстрая проверка состояния — пункты 13 (место и квота) и 14 (диагностика доступа) меню.

## Доступ и авторизация

### `401 Unauthorized` / «Не авторизован»

Токен недействителен: отозван, выпущен для другого аккаунта или скопирован не целиком. Лечение — пункт 18 (переавторизация) либо новый токен. Проверка живости токена:

```powershell
$h = @{ Authorization = "OAuth $tok" }
try { (Invoke-RestMethod "https://cloud-api.yandex.net/v1/disk/" -Headers $h).total_space } catch { "HTTP " + [int]$_.Exception.Response.StatusCode }
```

`HTTP 401` — токен мёртв, `HTTP 410` — доступ закрыт на стороне сервиса, число — токен рабочий (объём Диска в байтах).

### `402 Payment Required` — `WebDAV is not available for the free tariff`

WebDAV закрыт на бесплатном тарифе. Не используйте remote типа `webdav` — нужен нативный backend `yandex` (см. раздел «Настройка доступа к Яндекс.Диску» в README).

### `410 GoneError` — «Ресурс больше недоступен»

Так отвечает встроенное приложение rclone, которое Яндекс заблокировал. Remote, созданный без `client_id`/`client_secret`, работать не будет — пересоздайте его со своим OAuth-приложением.

### `403` / `Insufficient scope`

Приложению не выданы права `cloud_api:disk.read` / `cloud_api:disk.write`. Исправьте права в настройках приложения на `oauth.yandex.ru`, затем переавторизуйтесь (пункт 18): старый токен сохраняет прежний набор прав.

### `429` / `509 Too Many Requests`

Троттлинг Яндекса. Снизить параллельность:

```powershell
rclone copy "ydisk:Папка" "<папка дисков>" --transfers 2 --checkers 4 --tpslimit 5
```

## Запуск и консоль

### Пустая консоль при двойном клике

Причины: концы строк `LF` в `.bat` (cmd ожидает `CRLF` и молча не выполняет блоки), отсутствие вывода в первые секунды (скрипт делает два запроса к Диску до отрисовки меню), шрифт консоли без кириллицы. В комплекте исправленный батник: `CRLF`, `title`, строка `Starting R2clone menu...`, `cd /d "%~dp0"`. Если окно пустое и после этого — запустите `cmd /k R2clone_menu.bat` и посмотрите текст ошибки.

### `Script not found`

Батник ищет `%~dp0R2clone_menu.ps1` рядом с собой. Переименовали или переместили `.ps1` — поправьте строку `set "SCRIPT=…"` либо верните имя.

### `rclone не найден в PATH`

Установите rclone и **перезапустите консоль**. Проверка: `Get-Command rclone`. Если установлен вручную — добавьте папку в `PATH` или пропишите полный путь.

### «Выполнение сценариев отключено»

Запускайте через `R2clone_menu.bat` (в нём `-ExecutionPolicy Bypass`) либо разово:

```powershell
powershell -ExecutionPolicy Bypass -File "<папка проекта>\R2clone_menu.ps1"
```

Менять политику на уровне системы не требуется.

### Кириллица в аргументах батника

`cmd` передаёт аргументы в своей кодировке, и путь вида `<папка дисков>\…`, переданный через `.bat`, может исказиться. Не передавайте `-LocalRoot` из батника — меняйте значение в `R2clone_menu.config.json` или в параметрах `.ps1`.

## Работа с файлами

### «Нет такого номера» на любой номер

Дефект версий до 1.1: список разбирался как вложенный массив, счётчик содержал один элемент. Исправлено; обновите `R2clone_menu.ps1`.

### Копирование «зависает» и идёт очень медленно

Проверьте пунктом 13 квоту и пунктом 14 доступ. При большом числе мелких файлов скорость ограничена числом запросов — уменьшите `--checkers`, при крупных файлах — `--transfers`. Обрыв соединения не страшен: повторите пункт 6, докачает.

### Пункт 8 скачал весь Диск вместо одной папки

Пункт действует на **текущую** папку. В корне это весь Диск. Сначала войдите в нужную папку (пункт 2), затем копируйте.

### Загрузка положила файлы не туда

Пункты 10–11 работают с **текущей** папкой Диска и не спрашивают путь на облаке. Проверьте строку «На Диске:» в предпросмотре перед подтверждением. Папка загружается в подпапку с именем локального источника.

### Загрузка перезаписала файл на Диске

`copy` перезаписывает совпадающие имена более новыми версиями. Чтобы сначала посмотреть план, запустите с `-DryRun`:

```powershell
R2clone_menu.bat -DryRun -NoGui
```

### Сверка (`check`) показывает расхождения

Сначала повторите копирование — обычно это файлы, которые не доехали из-за обрыва. Если расхождения остаются, проверьте `--checksum`: для части хранилищ хэшей нет, и rclone сравнивает только размер.

## Настройки и пути

### Локальная папка не та

Пункт 12 показывает источник: параметр `-LocalRoot`, файл настроек или значение по умолчанию `<папка дисков>\<remote>`. Сброс — пункт 12 → «3».

### Скрипт не видит настройки

Файл называется `R2clone_menu.config.json` и лежит рядом со скриптом. Проверьте, что это валидный JSON:

```powershell
Get-Content .\R2clone_menu.config.json -Raw | ConvertFrom-Json
```

### Путь длиннее 260 символов

Windows не умеет работать с такими путями без включённой поддержки длинных путей. Скрипт предупредит заранее; выберите локальную папку короче.

## Диагностика

```powershell
rclone version                 # версия rclone
rclone listremotes             # список remote
rclone lsd ydisk: --max-depth 1 # доступ к корню
rclone about ydisk: --json     # квота
```

В шапке меню для remote типа `yandex` должна быть строка «Доступ к Диску: официальный API Яндекса» — если её нет, remote не распознан как Яндекс.Диск.

Журнал операций — рядом с локальной папкой (`rclone-copy.log`), пункты 15–16 меню показывают ошибки и открывают файл.
